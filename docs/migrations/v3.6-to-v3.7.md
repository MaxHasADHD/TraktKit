# TraktKit 3.7.0 Migration Guide

## Overview

TraktKit 3.7.0 updates to **SwiftAPIClient 1.7.0** and reworks the authentication
lifecycle so that an **expired token is a signed-in state**, not an error. This
fixes a class of bugs where authenticated users were pushed back through the
sign-in flow after their access token expired (for many apps, once a day — Trakt
access tokens last 24 hours).

Alongside the auth fix, `fetchAllPages()` gains a richer result type that no
longer silently hides failed pages.

Most apps need only a handful of small changes. The compiler will flag every one.

## Why the change?

Previously, loading an **expired** token threw an error. TraktKit's auth cache
was therefore never populated for a user whose token had lapsed, so
`isSignedIn` reported `false` — indistinguishable from a user who had never
signed in — even though a valid refresh token was sitting in the Keychain. Apps
reacted by showing the re-authentication flow.

In 3.7.0:

- An expired token is returned as a normal `AuthenticationState` with
  `isExpired == true`. `isSignedIn` stays `true`.
- The token is refreshed on demand (proactively before requests, and reactively
  on a 401) through the shared `AuthCoordinator`.
- The **only** way back to signed-out is an explicit `signOut()` (or genuinely
  empty storage).

## What Changed?

### 1. `fetchAllPages()` returns `PagedFetchResult` (was `Set`)

`Route.fetchAllPages()` now returns `PagedFetchResult<Element>` instead of
`Set<Element>`. This lets it report partial fetches instead of silently
returning an incomplete `Set`.

**Before (3.6.x):**
```swift
let shows: Set<TraktWatchedShow> = try await traktManager.sync()
    .watchedShows()
    .extend(.Full, .progress)
    .limit(100)
    .fetchAllPages()

print("Fetched \(shows.count) shows")
```

**After (3.7.0):**
```swift
let result = try await traktManager.sync()
    .watchedShows()
    .extend(.Full, .progress)
    .limit(100)
    .fetchAllPages()

let shows: Set<TraktWatchedShow> = result.items
print("Fetched \(shows.count) shows")

// New: detect partial results instead of trusting an incomplete Set.
if !result.isComplete {
    for failure in result.failedPages {
        print("Page \(failure.page) failed: \(failure.error)")
    }
}
```

Notes:
- A **first-page** failure still throws (nothing was fetched).
- A **later-page** failure returns the partial `items` with the missing pages in
  `failedPages`, rather than throwing or silently truncating.
- New optional `retryLimit:` parameter is forwarded to each page request. Pass
  `0` to fail fast instead of sleeping through Trakt's rate-limit `retry-after`
  (which can be up to 5 minutes):
  ```swift
  let result = try await route.limit(100).fetchAllPages(retryLimit: 0)
  ```

### 2. `checkToRefresh()` → `refreshTokenIfNeeded()`

The method that ensures a valid access token before authenticated requests has a
clearer name.

**Before:**
```swift
try await traktManager.checkToRefresh()
```

**After:**
```swift
try await traktManager.refreshTokenIfNeeded()
```

> **You may not need to call it at all.** SwiftAPIClient now refreshes proactively
> before a request when the token is near expiry, and reactively on a 401. A plain
> `.perform()` on an authenticated route self-heals. Keep calling
> `refreshTokenIfNeeded()` at launch if you want to surface sign-in state up front,
> but authenticated requests no longer depend on it.

### 3. Auth errors: expiry is no longer an error

`AuthenticationError.tokenExpired(refreshToken:)` and `.noStoredCredentials` are
**removed**. `.notConfigured` (a setup error) is the only remaining case.

- **Expiry** is now read from `AuthenticationState.isExpired`.
- **Missing credentials** are represented by a `nil` state.
- `refreshTokenIfNeeded()` refreshes an expired token internally and throws
  `TraktClientError.userNotAuthorized` only when there are genuinely no stored
  credentials.

**Before:**
```swift
do {
    try await traktManager.checkToRefresh()
} catch AuthenticationError.tokenExpired {
    // ...token was expired
} catch AuthenticationError.noStoredCredentials {
    showSignIn()
}
```

**After:**
```swift
do {
    try await traktManager.refreshTokenIfNeeded()
} catch TraktClientError.userNotAuthorized {
    // Genuinely no stored credentials (never signed in, or signed out).
    showSignIn()
} catch TraktClientError.missingClientInfo {
    // Client isn't configured (no AuthCoordinator).
}
```

> **Important — don't sign users out on transient errors.** TraktKit never clears
> credentials on its own; it only throws. A network failure, timeout, or a
> refresh that fails due to connectivity must **not** trigger your
> re-authentication UI — the stored refresh token is still valid and will succeed
> later. Reserve the sign-in flow for `TraktClientError.userNotAuthorized` and
> `TraktClientError.invalidRefreshToken` (Trakt rejected the refresh token itself).

### 4. Custom `TraktAuthentication` implementations

If you provide your own `TraktAuthentication` (i.e. `APIAuthentication`) storage
instead of `KeychainTraktAuthentication`, update `getCurrentState()`. It is now
**non-throwing** and returns an **optional**:

```swift
func getCurrentState() async -> AuthenticationState?
```

Rules:
- Return whatever credentials exist — **even expired ones**.
- Return `nil` **only** when nothing is stored (never signed in, or signed out).
- Do not throw on expiry; the caller checks `AuthenticationState.isExpired`.

**Before:**
```swift
func getCurrentState() async throws(AuthenticationError) -> AuthenticationState {
    guard let accessToken, let refreshToken, let expirationDate else {
        throw .noStoredCredentials
    }
    guard expirationDate > .now else {
        throw .tokenExpired(refreshToken: refreshToken)
    }
    return AuthenticationState(accessToken: accessToken, refreshToken: refreshToken, expirationDate: expirationDate)
}
```

**After:**
```swift
func getCurrentState() async -> AuthenticationState? {
    guard let accessToken, let refreshToken, let expirationDate else {
        return nil
    }
    // Return even expired credentials; the caller reads `.isExpired`.
    return AuthenticationState(accessToken: accessToken, refreshToken: refreshToken, expirationDate: expirationDate)
}
```

If your storage can hold tokens without a persisted expiration date (e.g. after
an app reinstall, when the Keychain survives but UserDefaults does not), return
`Date.distantPast` as the expiration so the state reads as expired and gets
refreshed — rather than returning `nil` and signing the user out. This mirrors
what the built-in `KeychainTraktAuthentication` now does.

### 5. `mutableRequest(...)` is now `async` (advanced)

Only relevant if you call `TraktManager.mutableRequest(...)` directly. It is now
`async` so it can await the coordinator's first storage load; add `await`:

```swift
let request = try await traktManager.mutableRequest(
    forPath: "oauth/device/token",
    isAuthorized: false,
    withHTTPMethod: .POST,
    body: body
)
```

## Migration Checklist

1. Update `.fetchAllPages()` call sites to read `.items` (and optionally check
   `.isComplete` / `.failedPages`).
2. Rename `checkToRefresh()` → `refreshTokenIfNeeded()`.
3. Remove any `catch AuthenticationError.tokenExpired` / `.noStoredCredentials`
   handling; treat only `TraktClientError.userNotAuthorized` /
   `.invalidRefreshToken` as "show sign-in."
4. If you have a custom `TraktAuthentication`, make `getCurrentState()`
   non-throwing and return `AuthenticationState?`.
5. Add `await` to any direct `mutableRequest(...)` calls.
6. Audit your error handling so transient/network errors don't sign users out.

## Compiler Support

Every change above is a breaking, compiler-enforced change. Run a build and the
compiler will point you at each call site that needs updating.
